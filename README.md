# SOUL ASCENSION — Phase 1

An original, offline anime-inspired action RPG prototype built in **Godot 4.4.1 / GDScript**. This is a playable source project, not an Android APK or store-ready release.

## Open and play

1. Install the standard **Godot 4.4.1** editor from https://godotengine.org/download/archive/4.4.1-stable/ . No .NET edition or API keys are needed.
2. Extract this ZIP. In Godot, choose **Import**, then select `SOUL_ASCENSION/project.godot`.
3. Allow the artwork to import, then press **F6** with `main.tscn` open, or **F5** to run the project.
4. Choose your name and fighter. Select **Begin Your Awakening**, then **Enter**.
5. Defeat the enforcer. Your first clear earns 120 XP and 250 Gold and advances you to level 2. Replays earn 55 XP and 100 Gold.

On a Chromebook, use the Linux version of Godot if Linux development support is enabled on the device. Hardware and graphics compatibility still need checking on your actual Chromebook.

## Controls

| Action | Keyboard | Touch |
| --- | --- | --- |
| Move | WASD | Left stick (fixed circle, or touch anywhere in the lower-left area) |
| Basic strike | J, hold to repeat | Hold STRIKE |
| Heavy attack | K | HEAVY |
| Dodge | Space (dashes in the direction you hold, otherwise away from the enemy) | DODGE |
| Block | Hold L | Hold BLOCK |
| Echo Pulse / stagger | Q | PULSE |
| Rift / ranged strike | E | RIFT |
| Mend / heal | R | MEND |
| Horizon Break ultimate | F, at 100% charge | ULTIMATE |

Move within striking distance. The enforcer's red circle telegraphs the position of its next attack. Dodge away or block. Basic attacks restore Aether; abilities consume it. Hits build ultimate charge. Auto-battle becomes available only after a first clear.

## Implemented

- Premium home composition with original generated character art and animated Aether motes.
- All requested home navigation entries. Unfinished systems explicitly open **planned feature** notices.
- Male/female prototype combat rigs, player naming, and a short text introduction.
- One story mission, one arena, one player, one enemy with pursuit and attack telegraphs.
- Basic/heavy attacks, dodge invulnerability, block mitigation, 3 skills, an ultimate effect, combos, critical hits and stagger.
- Original procedural impact particles, weapon arcs, screen shake and synthesized sound effects.
- Win/loss and retreat flows; no rewards on loss or retreat.
- XP, level progression, growing combat stats, power score and hero inspection.
- Gold, zero-initialized Crystals, mission energy and offline regeneration.
- Local versioned saves, atomic replacement, backup recovery and validation.
- Persistent sound, shake and reduced-background-motion settings.
- Landscape touch layout with independent finger IDs for movement and attack.
- Completed-stage auto-battle prototype.

## Deliberately not implemented yet

Summons, extra playable heroes, gear, upgrade materials, star progression, transformations, elemental matchups, boss missions, purchase processing, ads, subscriptions, VIP benefits, battle-pass rewards, achievements/reward claims, cloud accounts, PvP, guilds, controller support, voice acting and full cinematic animation. Their future status is explicit in the UI and roadmap. The ultimate preview in the hero screen is labeled **Aether Pose Preview**, because it is only a prototype pose effect.

The hero home artwork currently shows the male design for both choices; the female choice changes the combat rig. This is disclosed in onboarding and on the home screen. Combat characters, scenery and audio are intentionally simple procedural placeholders. There is no full anime sprite-animation asset set yet.

## Save behavior

Godot writes `user://soul_ascension_v1.json` and a `.bak` on this device. It saves on identity/settings changes, mission entry, mission settlement, energy regeneration and application pause. Closing a mission consumes its entry energy without granting rewards. Values are validated; a damaged primary file falls back to its backup. Save failures are surfaced in the UI.

These are offline prototype saves: checksums detect accidental damage, **not cheating**. Device-clock energy regeneration is not secure enough for a paid/competitive economy. Cloud migration must add authenticated accounts, server time, authoritative currency/mission settlement and purchase receipt verification. No real purchase record is generated by this build.

## Tests

From the project directory with Godot on PATH:

```sh
godot --headless --editor --import --quit
godot --headless --script res://tests/test_phase1.gd
godot --headless --script res://tests/test_live_combat.gd
godot --headless --script res://tests/test_repairs.gd
```

See `docs/REPAIR_LOG.md` for the takeover repair pass and a list of what is still placeholder.

Run tests using a separate `XDG_DATA_HOME` on Linux so test accounts do not replace a player's save. The delivered validation report records the actual checks performed. Desktop rendering and programmatic multitouch checks do not substitute for Android device testing.

## Android build preparation

An ARM64 Android export preset is included. It has **not been exported or tested on a phone** in this delivery. No signing credentials are included.

For Godot 4.4.1, install matching export templates, OpenJDK 17 and the Android SDK, then configure their paths in Editor Settings → Export → Android. Open Project → Export → Android and export a **debug APK** for local device testing. Godot's official 4.4 instructions are authoritative:
https://docs.godotengine.org/en/4.4/tutorials/export/exporting_for_android.html

Check `com.newroots.soulascension` before first publication. Store publication, release keystore setup, billing, privacy paperwork and a signed AAB are later tasks. The project requests no Internet permission. Pure GDScript and engine-neutral gameplay modules leave a path to a later iOS export; no iOS build has been created.

## Project map

- `scenes/` — engine entry scene.
- `scripts/core/` — profile and session coordination.
- `scripts/combat/` — battle, fighter, touch controls, joystick, scenery and visual effects.
- `scripts/characters/` — stats and original hero definitions.
- `scripts/economy/` — currency spending and energy regeneration.
- `scripts/progression/` — XP and leveling.
- `scripts/missions/` — mission catalog; only 1-1 is executable.
- `scripts/save/` — local persistence backend.
- `scripts/ui/` — screen composition, reusable UI styles and atmosphere.
- `scripts/audio/` — synthesized prototype sound effects.
- `scripts/settings/`, `inventory/`, `shop/`, `summoning/` — documented future module boundaries.
- `docs/` — story bible, phased roadmap, asset provenance, validation and rendered screenshots.

No services were purchased, no real-money transactions were made, and no secrets are stored in the project.
